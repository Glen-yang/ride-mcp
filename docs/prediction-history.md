# Prediction historical risk metrics

Prediction candidates previously returned null historical ROI/drawdown. The first repair added a native economic-PnL path, but many upstream points carry old observations and some wallets lack a complete lifetime funding ledger. Those remain unavailable in that path; the checks are not relaxed.

## Reconstruct historical equity independently

The Agent bridge can now reconstruct a one-month daily inventory curve from the configured Polygon RPC and official Polymarket prices:

1. Fix a confirmed chain block, network 137, and a common UTC daily grid covering at least 28 days.
2. Enumerate current OPEN and REDEEMABLE_LOST outcome inventory, plus every relevant ERC-1155 transfer in the window. Losing unredeemed positions must be included because they can have had positive historical value.
3. Follow both directions of `alchemy_getAssetTransfers` to explicit completion for the two collateral tokens and configured CTF contract. Retain raw integer ERC-20 and ERC-1155 amounts, token IDs, blocks and timestamps; de-duplicate self-transfers by log identity.
4. Read actual cash and batch outcome balances at the end block, reverse the complete transfers to each historical instant, then independently read every balance at the start block. Every reconstructed boundary balance must match exactly. Wallet activity and chain transfers cross-check financial transaction coverage. Missing activity rows for direct ERC-20 transfers or exact Safe CALL transfers are independently decoded and matched to actual token/amount/from/to evidence as external capital. Arbitrary calls and delegatecalls are not inferred; complete 1:1 USDC.e/pUSD wrap or unwrap receipt pairs are internal conversions rather than external capital. Other unclassified movements fail closed.
5. Value historical holdings from `/v2/prices-history`. A three-hour aggregate can be used only after its observation window has ended, with at most six hours of price age. No future price or unlimited carry-forward is allowed. The current anchor additionally uses a point-in-time price read, preserving the 1% reconciliation limit rather than widening it to accommodate a three-hour average. Actual CTF payout numerators/denominators determine settlement prices. The payout slot is derived by matching the actual token ID against CTF collection IDs and on-chain collateral identities; external outcome labels and CLOB indices are not assumed to be payout indices. Archive reads locate the first settled block when necessary, so current settlement cannot be applied to earlier holdings.
6. Compare current marked equity with the independent official accounting snapshot, retaining the existing maximum 1% discrepancy rule and its exact disclosed value. Recheck the anchor block hash to reject reorgs.

`E = cash + sum(outcome quantity * observed price)`. Link unit NAV using `(E[i] + interval withdrawals) / (E[i-1] + interval deposits)`; maximum peak-to-trough unit-NAV decline is drawdown, and cumulative unit-NAV change is ROI. Current and historical balances include actual trading fees, redemptions and wallet income without needing missing PnL atoms or a lifetime initial-deposit event. The complete activity feed identifies external deposits/withdrawals and tips for capital-flow adjustment. All arithmetic uses integer raw token units and Decimal.

The results remain **daily sampled, cashflow-adjusted estimated account performance**, with explicit window, basis, three-hour mark resolution, maximum mark age, block range/hash, transfer/token counts and reconciliation difference. They are not all-time/intraday maximum drawdown, follower results, or a future loss bound. Sampling and interval cashflow timing can miss losses within a day. The supported reconstruction scope is the configured v1 CTF contract and two collateral tokens; unsupported token modules, missing prices, incomplete pagination or unclassified transfers remain unavailable with a reason.

## Availability and compatibility

Reconstruction runs outside recommendation latency, at most two wallet jobs and six external HTTP requests at a time, with read-only RPC calls batched in groups of at most twenty and a bounded shared historical-price cache, with a five-minute deadline per wallet. Verified metrics and curve evidence are persisted in the private Agent `ride_agent_prediction_history` cache under opaque trader IDs. A one-hour background refresh retains an earlier verified result only within the existing 36-hour history freshness window. Fresh records survive process restarts. While reconstruction is pending, the original validated PnL path remains available; missing evidence never becomes zero. Scores remain discoverable independently of history availability. No legacy App table, API, approved plan or execution path is changed.

The source contracts are the official [Polymarket v2 Data API](https://data-api.polymarket.com/v2/docs), the official SDK's [accounting snapshot route](https://github.com/Polymarket/py-sdk/blob/main/src/polymarket/_internal/actions/data.py), and [Alchemy's Transfers API](https://www.alchemy.com/docs/data/transfers-api/transfers-endpoints/alchemy-get-asset-transfers).

New recommendations also penalize partially shared topic/asset sets using intersection over union. Exact asset matches keep their existing penalty; style, direction and market penalties remain. This improves topic diversity without fabricating measured loss correlation or changing existing saved portfolios.

The configured portfolio loss trigger, Prediction 1x cap, 50 USDC per-trader minimum, live execution preflight and final human confirmation remain in force.
